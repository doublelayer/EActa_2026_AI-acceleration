# Package layout

The root contains PROMPT.txt, AGENTS.md, four figure-generation notebooks and Electrochimica_Acta_research_article_refernce.docx. This package now uses review-driven versioning; the reference DOCX is excluded from drafting and construction.

instructions/ contains role and writing guidance. article/ contains facts, bibliography, sentence plan, versioned Markdown/DOCX files, image resources, review records and the database-only input manifest. journal/, literature/ and environment/ contain their declared supporting inputs. tools/ contains the database fingerprint check and TOC generator. source_data/ contains the supplied publication-page image and the Figure 4 source bundle in `source_data/figure4/`. The notebooks and TOC generator read DASC databases from the parent project root and Figure 4 CSV/JSON inputs from the package; none of these inputs are downloaded. `inputs/run_.../` holds run-specific ledgers, checkpoints, integrity results and working files.

Run `python tools/verify_package.py` to compare the five source database baselines with `article/input_manifest.json`; a changed or missing database produces an alert and does not fail the check. This verifier does not inspect other files. Run `python tools/verify_article_archive.py` at intake and after archiving to validate indexed artifact presence, archive structure, exact image references, resource-folder parity, and review-record content. Figure notebooks and the TOC generator are not run for routine revisions; use them only if a specific review item requires a change and the necessary work is authorized. Git tracks file changes. Run `python tools/prepare_manifest.py` to remove unrelated entries while preserving unchanged database baselines. Use `python tools/prepare_manifest.py --accept-current` only after reviewing and intentionally accepting changed database sources.

## Manuscript and DOCX review flow

Each version is kept as an editable Markdown draft at `drafts/article_draft_vN.md`, its used images under `article_resources/vN/`, and the generated review DOCX at `manuscript_versions/Electrochimica_Acta_research_article_draft_vN.docx`. See `version_index.md` for paths and `reviews/review_index.md` for comment and revision counts. Future versions use the next unused version number.

Each next article run reads the latest archived Markdown draft, its paired reviewed DOCX, that version's complete `reviews/review_vN.md`, `reviews/review_index.md`, and applicable user-supplied review files. The DOCX comments, tracked edits, and direct text changes from review are the revision items. Compare DOCX text with the Markdown, record each item's disposition, and make only changes needed to resolve those items. Do not invent or add unrelated claims, sections, analysis, citations, or figures. Older review records remain historical and are consulted only when the latest review points to them.

Every archived DOCX has a `reviews/review_vN.md` record containing its complete text, tracked insertions/deletions, and embedded Word comments with their anchor paragraphs. The DOCX remains authoritative for layout and figures. Reviewers may edit/comment on it in Google Drive or another service. Before starting the next version, replace the matching DOCX in `manuscript_versions/` with the reviewed file and regenerate the matching review record with `python tools/extract_docx_comments.py --docx article/manuscript_versions/Electrochimica_Acta_research_article_draft_vN.docx --overwrite`. Then update the comment and revision counts in `reviews/review_index.md` and `version_index.md`. The Markdown and DOCX are aligned when generated; the reviewed DOCX may then differ and becomes the source for the next revision. User-supplied review files remain unchanged.

The archive has 23 complete DOCX review records. Six DOCX files contain 54 Word comments; tracked insertions and deletions are also preserved separately from comments. Version 52 contains no Word comment threads, but its review record includes the full DOCX text and 89 insertions/84 deletions. Do not create `prior_run_review.md` or versioned `release_review_vN.md` files. See `version_index.md` and `reviews/review_index.md` to locate versions and review records.
